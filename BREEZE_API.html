Interpreted Breeze applications and scheduled services

Quick start

Create the controls, place them in a layout, register events, then show the completed window.

let main = window("My App", 120, 100, 600, 400);
let root = windowRoot(main);
let status = statusBar();
dock(root, status, "bottom");
let statusText = statusPanel(status, "Ready", 400);
let body = stackPanel("vertical");
dock(root, body, "fill");
let input = textField("World", 26);
let action = button("Greet", 100, 28);
stack(body, input);
stack(body, action);

on action.click {
    set statusText.text = "Hello, " + value(input, "text");
}

show(main);
Scripts are loaded from 0:\Apps. The current temporary disk remains available until Windose restarts.

Tutorial: Create a windowed process

Save this as 0:\Apps\hello.breeze, open it in Breeze Editor, and choose Run Script.

Build and show the application

Tutorial
let app = process("Hello App");
let main = window("Hello", 140, 100, 480, 260);
let root = windowRoot(main);
let body = stackPanel("vertical");
let output = panel("Ready", 28);
let greet = button("Greet", 100, 28);

dock(root, body, "fill");
stack(body, output);
stack(body, greet);

on greet.click {
    set output.text = "Hello from Breeze";
}

show(main);

process supplies the Task Manager name and keeps the program alive without windows. Call stopProcess(app) from its Exit command, or omit process when final-window closure should end it automatically. Build controls before calling show.

Tutorial: Create a headless process

Run periodic work without a window

Tutorial
let worker = process("Clock Logger");
let pulse = timer(1000);

on pulse.tick {
    log("Clock: " + clock());
}

Choose Run Script. The process remains in Task Manager and logs once per second. Prefer timers over doing expensive work in every update event.

Tutorial: Create a managed service

Save this as 0:\System\Services\indexer.breeze and choose Run Background.

Watch the Documents directory

Tutorial
let indexer = service("Document Indexer", true, false);
watchPath("0:\\Documents", true);

on indexer.message {
    if (value(event, "name") == "filesystem.changed") {
        let change = value(event, "data");
        log("Changed: " + value(change, "path"));
    }
}

The second argument enables bounded crash restart. The third controls protection from ordinary stop requests. Services execute cooperatively, so handlers must return quickly. The temporary filesystem does not survive restart; automatic boot loading becomes persistent when a durable backend is installed.

Tutorial: Send messages between programs

Service receiver

Tutorial
let indexer = service("Document Indexer", true, false);

on indexer.message {
    if (value(event, "name") == "scan") {
        let files = getFiles(value(event, "data"));
        reply(event, listCount(files));
    }
}

The service receives a directory and replies with its immediate file count.

Windowed client

Tutorial
let client = process("Indexer Client");
let main = window("Indexer Client", 180, 140, 420, 220);
let root = windowRoot(main);
let scan = button("Scan Documents", 150, 28);
let status = panel("Idle", 28);
dock(root, scan, "top");
dock(root, status, "top");

on scan.click {
    let indexer = tryFindProcess("Document Indexer");
    if (indexer != null) {
        request(indexer, "scan", "0:\\Documents");
    } else {
        set status.text = "Service is not running";
    }
}

on client.message {
    if (value(event, "name") == "scan.reply") {
        set status.text = "Files: " + value(event, "data");
    }
}

show(main);

request assigns a correlation ID. reply returns it through replyTo. Use send when no response is needed.

Tutorial: Store settings safely

Handle an expected missing file

Tutorial
let path = "0:\\Documents\\settings.txt";
if (!fileExists(path)) {
    writeFile(path, "automatic", false);
}

let result = tryReadFile(path);
if (value(result, "ok")) {
    log("Mode: " + value(result, "value"));
} else {
    log(value(result, "error"));
}

tryReadFile returns ok, value, and error. Filesystem mutations return booleans so expected failures do not terminate a service.

Tutorial: Create and import a module

Create a reusable function

Tutorial

Save the first file as 0:\Apps\lib\format.breeze, then import it from an application in 0:\Apps.

// lib/format.breeze
function formatCount(value) {
    return "Items: " + value;
}

// main.breeze
import "lib/format.breeze";
log(formatCount(12));

Relative paths resolve from the importing file. A normalized module executes once per application and shares its scope and capabilities.

Extending Breeze

To add a new Breeze function, wire it through four places:

Concept

Add its runtime implementation in BreezeRuntime.CallNative():

                
case "fileExists":
    return FileSystemManager.Current.FileExists(ToText(args[0]));

Declare its argument count in BreezeRuntime.GetExpectedArgumentCount():

                
"fileExists" => 1,

Add it to editor completion in CodeEditor.CompletionItems:

                
"fileExists",

For a new Object type:

Concept

Define the class object:

                
public sealed class BreezeObject
{
    public int Value;
}

Expose properties through BreezeRuntime.GetProperty():

                
if (target is BreezeObject breezeObject)
{
    if (property == "value")
        return (double)breezeObject.Value;
}

Allow assignments through BreezeRuntime.SetProperty():

                
if (target is BreezeObject breezeObject)
{
    if (property == "value")
        breezeObject.Value = ToInt(value);
    return;
}

Language statements

let

Statement

Creates a named value. Variables can hold strings, numbers, booleans, controls, windows, and returned native objects.

Variable assignment

Statement

Changes an existing variable. Variables declared inside a function are local to that call.

Statement

Comments and expressions

Syntax
// Arithmetic: + - * /
// Comparison: == != < <= > >=
// Logic: ! && ||
let message = "Count: " + (4 * 3);

+ joins values when either side is text. Logical AND and OR short-circuit.

Statement

else if chains are supported.

Statement

Loops are limited to 10,000 iterations, and each run or event is limited to 100,000 operations.

Native API

watchPath(path, recursive)

Filesystem

Subscribes the current Breeze process to changes reported by the active filesystem. A matching change is queued as a normal process message named filesystem.changed. The function does not call a separate callback and does not return the changed file.

watchPath(path, recursive) -> boolean

Parameters

NameTypeDescription
pathstringFile or directory path to monitor. Relative paths are normalized under 0:\.
recursivebooleanfalse matches only that exact normalized path. true also matches every file and directory below it.

Returns

true when the watch was registered. Returns false when no filesystem backend is active.

Delivered message

ExpressionValue
value(event, "name")filesystem.changed
value(event, "sender")filesystem
value(change, "type")Created, Modified, Deleted, or Moved
value(change, "path")The new or affected normalized path.
value(change, "previousPath")The old path for a move; otherwise an empty string.

Example

let watcher = process("Document Watcher");
let watching = watchPath("0:\\Documents", true);

on watcher.message {
    if (value(event, "name") == "filesystem.changed") {
        let change = value(event, "data");
        log(value(change, "type") + ": " + value(change, "path"));
    }
}

Registering a watch keeps a windowless process alive. Messages use the normal bounded process queue, so handlers should return quickly.

clearWatches()

Filesystem

Unsubscribes every filesystem watch registered by the current Breeze process. It does not remove watches owned by other processes and does not delete any files.

clearWatches() -> boolean

Parameters

None.

Returns

Always returns true after clearing the process's watch list.

Example

let watcher = process("Document Watcher");
watchPath("0:\\Documents", true);

// Stop receiving filesystem.changed messages.
clearWatches();
stopProcess(watcher);

Windose also removes these subscriptions automatically when the owning process terminates or fails.

System registry

Registry overview

Concept

The registry is a case-insensitive hierarchy of named settings. Separate key segments with /. Application settings belong below Apps/<application name>; protected operating-system settings live below System/.

registryDefine("Apps/Notes/Autosave", true,
    "Save the current document automatically.", false);
registrySet("Apps/Notes/Autosave", false);
let enabled = registryGet("Apps/Notes/Autosave");

Values are saved through IWindoseFileSystem in 0:\System\registry.db. The current memory filesystem keeps them while Windose is running; installing a persistent filesystem backend makes the same registry durable across reboots.

Registry permissions

Security

registry.read permits reads. registry.custom.write permits creation and modification outside System/ and is granted to normal applications. registry.write permits protected system changes and must be granted by native policy; trusted system services receive it automatically.

BreezeCapabilityPolicy.Grant(
    @"0:\Apps\settings.breeze", "registry.write");

Desktop settings

Tutorial
registrySet("System/Desktop/BackgroundColor", "#202840");

The desktop subscribes to this key and redraws immediately. Colors use #RRGGBB. System/Desktop/Wallpaper and System/Desktop/WallpaperMode are reserved for bitmap wallpaper support and currently do not draw an image.

Display settings

Tutorial
registrySet("System/Display/Width", 1920);
registrySet("System/Display/Height", 1080);
registrySet("System/Display/BitsPerPixel", 32);

if (registryRestartRequired()) {
    log("Restart required for the requested display mode");
}

These keys describe the desired boot mode. Limine GOP chooses the framebuffer before Windose starts, so changing them cannot resize the active screen. A future display bootstrap can consume them during boot. System/Display/CurrentWidth and CurrentHeight report the active framebuffer and are runtime-only.

Native C# API

Native API
SystemRegistry.Define(
    "Apps/MyApp/Theme", "classic", "Selected visual theme", false);
SystemRegistry.Set("Apps/MyApp/Theme", "dark");

SystemRegistry.Changed += change => {
    // change.Key, OldValue, NewValue, and Deleted
};

Define creates a documented default without overwriting an existing user value. Set updates and saves a value. Components can subscribe to Changed for immediate redraw or behavior updates, and must unsubscribe when disposed.

Processes

Processes and services

Concept

A process is a running program and its execution state. It has an ID, lifecycle, performance statistics, and optionally windows. A service is a background system role performed by a process, normally managed through automatic startup, dependencies, restart policy, and ordered shutdown.

Windose provides normal processes, scheduled processes, and Breeze services with discovery, dependencies, protection, startup, stop/restart control, and bounded automatic crash recovery.

ProcessStartInfo

Native C# API
process.startInfo = new ProcessStartInfo {
    Name = "Indexer",
    ExecutablePath = @"0:\Apps\indexer.breeze",
    Arguments = "--full",
    WorkingDirectory = @"0:\Apps",
    RestartFactory = () => new IndexerProcess()
};

Stores the launch identity needed by Task Manager. Restart creates a fresh instance through RestartFactory; Open File Location uses ExecutablePath; Properties displays all descriptor fields. Processes without a restart factory cannot be restarted.

process / stopProcess

Runtime
let worker = process("File Indexer");

on worker.update {
    // Perform a small amount of background work.
}

stopProcess(worker);

process(name) creates a headless Breeze process and names the current application process. It appears in Task Manager and remains alive without a window. stopProcess(process) stops it and closes its owned windows. Read its name and running properties with value.

The update handler runs cooperatively once per scheduler update, not on a separate thread, so it must return quickly.

Native C# process protection

process.canTerminate = false; // Protected from End Task.
process.canTerminate = true;  // User may end it.

Native processes are protected by default, while Breeze application processes are terminable by default. Breeze scripts cannot change canTerminate yet; protection is currently a native C# setting.

timer

Runtime
let clock = timer(1000);

on clock.tick {
    print("tick");
}

stopTimer(clock);
startTimer(clock);

Creates a repeating millisecond timer. Its tick handler runs cooperatively during the owning process update. Read the interval and active properties with value.

Process messages

Runtime
// Receiver
let app = process("File Indexer");
on app.message {
    print(value(event, "sender"));
    print(value(event, "name"));
    print(value(event, "data"));
}

// Sender
let target = findProcess("File Indexer");
send(target, "scan", "0:\\Documents");

findProcess(name) obtains a running named Breeze process. send queues a named value for it and returns false if its bounded queue is full. Messages are delivered in order with a limited number processed per scheduler update.

tryFindProcess returns an empty value when absent. broadcast(name, data) publishes to every other named Breeze process and returns the delivery count.

request(target, name, data) returns a correlation ID. The receiver uses reply(event, data); the response exposes the original ID through value(event, "replyTo").

System services

Runtime
let indexer = service("File Indexer", true, true);
serviceDependency("Storage");

on indexer.message {
    log(value(event, "data"));
}

service(name, restartOnFailure, protected) declares a scheduled program as a managed service. Startup programs use startService(path), stopService(name), restartService(name), and serviceState(name). dependenciesReady() checks registered dependencies. Crash restart is capped at three attempts.

Windose runs 0:\System\Services\startup.breeze at boot; it launches every other Breeze file in that directory.

Background programs

Runtime
let worker = scheduledProcess("File Indexer");
let files = getFiles("0:\\Documents");
let index = 0;

while (index < listCount(files)) {
    print(fileName(listGet(files, index)));
    index = index + 1;
}

Start this source with Run Background in Breeze Editor. It runs cooperatively without creating a Cosmos thread. Update handlers run at most every 100 ms, idle services execute at most every 250 ms, and messages make them eligible on the next desktop update. getDirectories and getFiles return lists of full paths; fileName extracts the final name.

Computation, lists, filesystem functions, timers, and process messages are allowed. GUI functions are rejected and stop only the background process. Use send to return results to a GUI application.

Complete system API

Service lifecycle

Reference
service(name, restartOnFailure, protected) -> service
serviceDependency(name)                    -> boolean
dependenciesReady()                       -> boolean
startService(path)                         -> boolean
stopService(name)                          -> boolean
restartService(name)                       -> boolean
serviceState(name)                         -> string

Services run as scheduled programs. Protected services reject normal stops. Failed opted-in services restart at most three times, resetting after 30 seconds of stable execution. Boot runs 0:\System\Services\startup.breeze, which launches the other service scripts.

Properties: name, state, running, protected, restartOnFailure, dependenciesReady. Events: update, message.

Process communication

Reference
findProcess(name)            -> process or error
tryFindProcess(name)         -> process or null
send(process, name, data)    -> boolean
broadcast(name, data)        -> delivered count
request(process, name, data) -> correlation ID or 0
reply(requestEvent, data)    -> boolean

Messages expose name, data, sender, id, and replyTo. Replies use the name <request-name>.reply. Each queue holds 128 messages and delivers at most 32 per update.

Capabilities are ui, filesystem.read, filesystem.write, registry.read, registry.custom.write, registry.write, ipc, logging, process.inspect, process.control, and service.control. System services are trusted. Protected registry, process, and service control otherwise require a native policy grant.

Current limitations

Breeze uses explicit result objects instead of language exceptions. It does not yet provide class inheritance, direct thread primitives, or persistent storage until a durable IWindoseFileSystem backend is available. Background services use scheduled processes, and GUI access from those workers remains intentionally blocked.
