Windose ELF Developer Docs

Write native x86-64 programs in C that run as first-class Windose apps — windows, widgets, files, processes.

Overview

Windose runs position-independent ELF64 binaries (ET_DYN) compiled with an ordinary C toolchain. Each program gets its own thread, pid, handle table, event queue and memory quota, plus a function table (KernelApi) with ~116 syscalls. Programs never touch the kernel directly — they call k_* wrappers from programs/include/kernel.h.

  • Ring 0, no isolation. A wild pointer can take down the kernel. Validate everything; the C side can't save you.
  • Handles, not pointers. UI objects come back as small ints (0 = failed). Never do arithmetic on them.
  • Event-driven UI. Clicks, keys, mouse and dialogs arrive as Event structs you poll.
  • Cooperative kill. kill closes a program's windows at once; its thread stops at its next kernel call. A pure compute loop that never calls in cannot be stopped — call k_yield() in hot loops.

Quickstart

# Linux / WSL
cd System/ELF/programs
sh build.sh hello          # -> bin/hello.elf
# Windows (clang)
build.bat hello            # -> bin\hello.elf

Deploy and run it inside Windose:

elf run /mnt/Programs/hello.elf   # runs to completion, prints exit code
elf list                            # running programs: pid, state, memory
elf kill 3                          # cooperative kill by pid
New binaries are staged at boot from embedded resources (Windose.csproj + Kernel.cs WriteStorage). If you add a program, add both lines or it won't ship.

Program anatomy

Normal main(argc, argv). crt0 checks the API version, builds argv via get_args, and turns your return value — or exit(code) from any depth (longjmp) — into the exit code.

#include <stdio.h>
#include "kernel.h"

int main(int argc, char **argv)
{
    handle_t win = k_create_window(320, 200, "Demo");
    if (!win) { puts("no window"); return 1; }
    handle_t btn = k_create_button(win, 20, 60, 140, 32, "Click me");
    handle_t lab = k_create_label(win, 20, 20, "Press the button");
    int clicks = 0;
    char text[32];
    for (;;) {
        Event e;
        while (k_poll_event(&e)) {
            if (e.type == EV_CLOSE && e.handle == win) { k_close(win); return 0; }
            if (e.type == EV_CLICK && e.handle == btn) {
                snprintf(text, sizeof text, "Clicks: %d", ++clicks);
                k_set_text(lab, text);
            }
        }
        k_sleep(10);   // never spin at 100% CPU
    }
}
Return codes: 0 = ok. Negative = error. K_KILLED (-100) means your program was killed — every wrapper calls exit(137) for you via __kchk. Handles: 0 = failed.

Building

  • build.sh [name] — gcc + binutils on x86-64 Linux. Needs gcc, ld, ar.
  • build.bat [name] — clang + ld.lld on Windows (winget install LLVM.LLVM; the Cosmos llvm-tools folder also works, no archiver needed). build.bat clean wipes obj/ + bin/.
  • Flags that matter: -fPIE + -pie --no-dynamic-linker -e _start (static PIE, ET_DYN), -mno-red-zone, -fno-stack-protector, -z norelro -z noseparate-code, --gc-sections. RELR relocations are supported, so modern linkers work unmodified.
  • Drop a new src/foo.c in and rebuild — it is picked up automatically. libc.a rebuilds from libc/*.c every time.

Bundled libc

  • string.h stdlib.h (malloc/free/calloc/realloc, strtol, qsort, bsearch, rand) stdio.h (printf family, puts, file_read) ctype.h, exit()/abort() from anywhere.
  • printf has no floats — %f/%e/%g print the literal text <float>. Format integers and strings; scale fixed-point yourself.
  • malloc sub-allocates from kernel chunks (pinned, zeroed, auto-freed at exit). free works; memory is never returned to the kernel mid-run.
  • Limits: no fopen (use file_read / k_write_file), no global constructors (.init_array), no TLS, no threads inside a program.

API reference

Every call below is the k_* wrapper (first pid arg filled in for you). Unless noted, 0 = ok, negative = error, 0 handle = failed.

Events

k_poll_event(&e) returns 1 with an event, 0 when the queue is empty. The queue holds 64 events and drops the newest when full — drain it every frame and k_sleep instead of spinning.

Widget guide

  • Coordinates are client-relative. (0,0) is the client's top-left; the frame and title bar are added for you. No manual offset math.
  • Creation binds automatically. Every created object is tracked and wired (clicks, selects, close) — you just handle the events.
  • Text round-trips with k_set_text / k_get_text (buttons, labels, fields, combo selection, tab titles, dialog results).
  • Text fields type natively (caret, selection, clipboard, focus). Your program still sees every key as EV_KEY; poll with k_get_text when you need the value.
  • Poll, don't push, for continuous values — sliders and progress bars have no change events; read them with k_slider_get in your loop.
  • Tab pages are parents — k_tab_add_page returns a handle you pass as parent to populate the page.
  • Popups take screen coordinates — convert with k_widget_screen_pos (returns (y << 16) | x). The bridge clamps to the screen.
  • Row identity is by index for lists/grids (re-query after add/remove); by handle for tree nodes, menu items and tabs.

Filesystem notes

  • Paths are absolute (/mnt/…). k_list_dir fills NUL-separated names, returns the count (-1 = missing/not-a-dir or buffer too small).
  • k_stat_file fills FileStat{is_dir, size_lo, size_hi}. k_read_file/k_write_file cap at 1 MiB per call — chunk big files.
  • k_delete_path is recursive and there is no recycle bin. Confirm destructive actions in your UI.
  • k_make_dir creates parents. k_rename_path fails if the destination exists.
  • k_list_drives gives mount points; k_drive_stat gives total/free bytes.
  • k_filedialog_open(title, initial, filter, save) is non-blocking: result arrives as EV_CLICK (a=1 chosen, 0 cancelled) and the path reads back with k_get_text on the dialog handle.
  • k_open_file(path) spawns .elf, else opens with the registered C# app.

Processes & limits

  • One thread per program, 512 KiB stack. Default quota 64 MiB per program (image + malloc), 16 MiB single alloc, 32 programs max, 256 objects per program — all tunable on ElfRunner.
  • k_spawn(path, argbuf, arglen) takes NUL-separated args, returns the child pid. k_kill is cooperative (windows close at once; the thread stops at its next kernel call — sleeps and polls check every ~10 ms). Killing yourself returns K_KILLED.
  • k_launch_app("explorer" | "terminal" | "editor" | "taskmgr" | "registry" | "settings" | "imageviewer", arg) opens built-in C# apps.
  • Program output (printf/k_write) goes to the system log as elf:<name>.

Desktops & notifications

  • 4 virtual desktops. k_desktop_count/current/switch; new windows open on the current one; k_window_set_desktop moves normal windows (pinned system windows refuse). Snap-on-drag and Alt+arrows are handled by the window manager.
  • k_notify_send(title, text) posts a toast + history entry (see it in the tray bell → notification center).
  • Drag onto your window with k_drop_accept(win, 1): you'll get EV_DROP + k_dnd_get_text.

ABI & versioning

  • KAPI_VERSION is currently 9. crt0 rejects older kernels (k->version < KAPI_VERSION → exit 127) and requires k->size to cover the struct.
  • Append-only. New syscalls go at the END of KernelApi in both kernel.h and ElfRunner.cs, pid first. Old binaries keep working on new kernels.
  • Adding a syscall: ① field + k_* wrapper in kernel.h ② same field + [UnmanagedCallersOnly] handler (Live(pid), try/catch, validate everything) + FillApi assignment ③ new OS access goes on IElfHost, implemented in WindoseBridge.cs. Then rebuild libc.a + all programs.

Troubleshooting

SymptomFix
Page fault on the first instructionHeap isn't executable: set ElfRunner.MakeExecutable to mark the pages.
Crash on the first kernel callABI mismatch: sysv_abi vs ms_abi must match the C# side. Rebuild libc + programs.
kernel API too old / exit 127Program built against an older kernel.h: rebuild.
unresolved symbol 'x'The program calls something not in libc: add it to programs/libc.
ET_EXEC linked at a fixed addressUse the provided build scripts (they link PIE).
Hotkey freezes the desktopHotkey actions run on the input thread and must return immediately — use k_spawn, never wait/block there.
System freezes on launchSame cause one level down: don't call blocking APIs from inside a hotkey or paint path.
